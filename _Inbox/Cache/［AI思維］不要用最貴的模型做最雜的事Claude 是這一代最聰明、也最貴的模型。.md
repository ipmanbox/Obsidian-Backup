

我把 Claude Code 從「偶爾玩玩」變成「每天真的靠它幹活」，中間卡關的，幾乎都不是技術問題，是沒人事先告訴我的幾個設定。
​
資料來源：學長Ethan〈Claude Code 保姆級攻略 2.0〉https://www.youtube.com/watch?v=Czky9q7sOWU
​
看完這支 27 分鐘的影片，我把跟自己經驗對得上、最有感的幾個整理出來——尤其適合「裝好了卻不知道怎麼用順」的人。
​
▋ 它不是越用越笨，是你的對話太長了
很多人覺得 Claude 用一用變鈍：忘記前面講過的、重複問、品質下滑。這不是壞掉，是「上下文視窗」滿了——它跟人一樣，記憶體有上限。解法很簡單：一個任務、一個對話，做完就開新的，別在同一個對話裡一直疊需求、改到爛。每次都要重講的規則，寫進 CLAUDE.md，它每次開場都會先讀。
​
▋ 先幫它戴上「不准亂刪」的安全帶
Claude Code 預設是：你授權它做什麼，它就做什麼。你說「幫我清這個資料夾」，它可能真的整個清光。所以每開新專案，我都會在 CLAUDE.md 先寫一條：「除非我明講，不可以刪除任何檔案、不可以做破壞性操作。」這樣它動手前會先問你。這條，比什麼炫技都重要。
​
▋ 不要用最貴的模型做最雜的事
Claude 是這一代最聰明、也最貴的模型。整理素材、轉格式、生初稿這種雜活拿它做，等於牛刀殺雞、純燒錢。日常任務可以交給便宜很多的模型（影片舉 DeepSeek 等，每百萬 token 價差 10 到 15 倍，搭某些方案甚至上百倍），真正要頂尖品質再切回 Sonnet 或 Opus。一個月花費有機會壓到原本一兩成。
​
▋ 從「問一句答一句」到「指揮一個團隊」
真正讓我點頭的是 Subagent：一個有「自己獨立記憶」的分身——你把調研、寫稿、審稿丟給不同分身去跑，它們各做各的，最後只交回成果，你的主對話保持乾淨不被塞爆。配上 skill（可重複呼叫的「技能卡」），你的角色就從「自己打字」變成「分派工作」。影片那句比喻很傳神：API 是引擎、CLI 是駕駛座、MCP 是車上的插孔。
​
▋ 拉回教學現場
我一邊教國文、一邊當資訊組長，這些不是工程師專利。校務的重複信件、報表、會議記錄交給便宜模型每天自動跑；要出題、做學習單草稿時才切回最強模型。先寫好 CLAUDE.md、設好保護規則、養成一任務一對話——光這三件，就能讓九成的人少踩九成的坑。
​
▋ 我的結論
工具紅不紅，從來不是「它能不能」，而是你願不願意花一小時把它設定對。多數人裝完就亂用、用爛了怪工具；分水嶺就在那一小時。AI 該幫你扛的，本來就是那 80% 的重複勞動——省下的時間，拿去陪家人、想更遠的事。
